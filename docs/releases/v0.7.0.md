# InferDoctor v0.7.0 - Evidence-Driven Application Diagnosis

InferDoctor v0.7 expands from local stack and responsiveness checks into evidence-driven diagnosis for local and hosted AI applications. It normalizes observable evidence, identifies the first broken layer, and proposes controlled next probes without replacing the frameworks, providers, or tracing systems being diagnosed.

## Dify and RAG Diagnostics

- Dify application diagnostics cover preflight, offline validation, safe smoke tests, performance reports, self-host reliability, read-only knowledge checks, and orchestration evidence.
- The Local / Private RAG Starter Kit provides a bounded reference workflow without automatic installation, DSL import, document upload, or knowledge-base creation.
- RAG Intelligence uses framework-neutral Case and Trace schemas for layered diagnosis, before/after comparison, and First Broken Layer attribution.

## Cognitive Diagnosis and Controlled Probes

- Cognitive diagnosis follows intent, route, plan, action, retrieval, context, generation, and postprocessing.
- The Minimal Next Probe Planner recommends the smallest useful evidence-gathering step.
- Controlled Cognitive Replay and the Gold Context Probe isolate capability from upstream retrieval and context failures.
- The OpenInference / OTLP adapter derives cognitive evidence from existing traces, including observable Agent-to-Tool plan evidence.

## Provider Foundation and OrcaRouter

- Provider presets are metadata layered over a single shared OpenAI-compatible transport.
- OrcaRouter is the first preset and remains replaceable provider metadata, not the center of the architecture.
- `inferdoctor provider list`, `provider show`, and `provider check` expose provider metadata and bounded connectivity, authentication, model-catalog, and optional invocation evidence.
- The default Provider Check uses an authenticated model-list request; a real chat request requires explicit `--smoke`.

## Privacy, Safety, and Diagnostic Independence

- API keys are read from provider-specific environment variables and are never rendered in results.
- Malformed keys and credentials embedded in endpoint URLs fail safely.
- Public endpoints require explicit `--allow-public`; private/LAN endpoints require explicit `--allow-non-local`.
- Optional chat response content is not retained.
- Provider partner metadata cannot influence diagnosis, scores, comparisons, rankings, or recommendations.

## Conservative Evidence Semantics

- A model appearing in `/models` proves catalog presence, not that the configured key can invoke it.
- HTTP 401 authentication failures remain distinct from HTTP 403 model-access denials.
- Unsupported `/models`, missing measurements, TTFT, pricing, and total compute cost remain `UNKNOWN` without direct evidence.
- Provider and performance smoke checks are bounded observations, not benchmarks or production capacity claims.

## Limitations

- Provider Compare, pricing data, routing, Doctor Recommendation, HTML reports, affiliate ranking, and paid audit workflows are not part of v0.7.
- Automated tests do not contact external provider APIs.
- Diagnostic quality remains limited by the evidence supplied by the application, trace source, or explicitly selected probe.
